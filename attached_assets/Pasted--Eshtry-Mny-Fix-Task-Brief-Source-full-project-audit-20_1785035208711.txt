## Phase 1 — Critical fixes (in this exact order)

**1. DB password never actually used**
Files: `User/config/db_conn.js:11`, `Product/config/db_conn.js:11`, `Cart/config/db_conn.js:11`
Check first: confirm the connection string literally has `***` instead of `${mongo_password}` — the audit flagged this might be a redaction artifact, not a real bug.
Fix: replace `***` with `${mongo_password}` in all three files.
Verify: start each service (or `docker compose up`) and confirm the logs show a successful Mongo Atlas connection, no auth error.

**2. Product/Cart crash on boot**
Files: `Product/routes/productRouter.js:3`, `Cart/routes/cartRouter.js:3`
Fix: copy `User/middleware/tokenValidationMiddleware.js` (~25 lines) into `Product/middleware/` and `Cart/middleware/`. Point both `require()` calls at the new local copy instead of `../../User/middleware/...`. Don't build a shared npm package — direct duplication is the intended fix (the resulting duplication is accepted, documented debt, not something to solve further right now).
Verify: `docker build ./Product` and `docker build ./Cart` each succeed; running each image boots with no `MODULE_NOT_FOUND`.

**3. Image tags pinned to `:latest`**
File: `eshtry-mny/values.yaml:6-9`
Fix: change all four image tags from `latest` to `0.1.0-dev`.
Verify: `helm template .` output has no `:latest` image reference.

**4. Helm secret.yaml can't render**
Files: `eshtry-mny/templates/secret.yaml`, `eshtry-mny/templates/externalsecret.yaml`, `values.yaml`, `values.example.yaml`
Check first: is there a working `SecretStore`/`ClusterSecretStore` actually applied in-cluster?
- If yes → delete `secret.yaml`; ESO is the real path.
- If no (likely for this project) → delete `externalsecret.yaml`; add a `secrets:` block (`mongoUsername`, `mongoPassword`, `accessToken`) with placeholder values to both `values.yaml` and `values.example.yaml`.
Verify: `helm template .` renders with no nil-pointer error on `.Values.secrets.*`.

**5. NetworkPolicies block DNS and Atlas**
Files: `networkpolicy-user.yaml`, `networkpolicy-cart.yaml`, `networkpolicy-product.yaml`
Fix (all three): add an egress rule allowing UDP+TCP 53 to the `kube-system` namespace.
Fix (`networkpolicy-user.yaml` only): add `Egress` to `policyTypes` (currently only `Ingress`); add the DNS rule plus a Mongo rule (below).
Fix (`networkpolicy-cart.yaml`, `networkpolicy-product.yaml`): replace the `podSelector: {app: mongodb}` rule with an egress rule allowing TCP 27017 to `0.0.0.0/0`. (Atlas is external SaaS — it has no small stable CIDR to allowlist unless you're on a paid tier with PrivateLink; if so, use that CIDR instead.)
Verify: first confirm your CNI actually enforces NetworkPolicy (Calico/Cilium/Weave do; plain Flannel doesn't). Then deploy with policies applied and check logs for an actual successful Mongo connection — not just pod status `Running`.

**6. Frontend calls the wrong paths (every request 404s)**
Files: `Home.tsx:18,46`, `Login.tsx:12`, `Profile.tsx:28`, `ProductInfo.tsx:20,40`, `Cart.tsx:27`, `CheckOut.tsx:14`, `Register.tsx:17`
Fix: add one exported constant (e.g. `front-end/src/config/api.ts` → `export const API_BASE = '/api/v1'`) and prefix every call above with it instead of hardcoding the prefix nine times. **Exception:** `Home.tsx:46` (category filter) becomes `${API_BASE}/filter/category/${cat}` — not nested under `/products`.
Verify: browser devtools network tab shows zero 404s across: home, product view, category filter, login, profile, add-to-cart, checkout.

**7. No authorization layer**
Files: `User/models/userModel.js`, the login/register controller that signs the JWT, `Product/routes/productRouter.js:11`
Fix: add `role: { type: String, enum: ['customer','admin'], default: 'customer' }` to the User schema; include `role` in the JWT payload at sign-time; add a `requireRole('admin')` middleware applied only to the create-product route, after the existing token-validation middleware.
Verify: create-product as a normal user → 403. Flag or create one admin user and confirm the same request succeeds for them.

## Phase 3 — High priority

**Security headers** — add `helmet` to all 3 Express services (`app.use(helmet())` near the top of each `server.js`). In `front-end/nginx.conf` add `X-Frame-Options`, `X-Content-Type-Options: nosniff`, a `Content-Security-Policy` restricting `connect-src` to same-origin/API host, `Referrer-Policy: strict-origin-when-cross-origin`. *Don't* also migrate the JWT out of localStorage here — that's a bigger separate change (httpOnly cookie + CORS credentials + CSRF); just flag it to Mina as a follow-up. Verify: `curl -I` shows the new headers.

**Service boundary violation** — already resolved by fix #2 above. Just confirm both middleware copies exist and match.

**Zero test coverage** — minimum viable only, not full coverage: Jest + Supertest smoke tests per backend covering `/health` returns 200 and one happy-path per service (register+login / list products / add-to-cart). Wire a real `test` script and add a Jenkinsfile test stage that fails the build on failure. Verify: `npm test` passes locally; Jenkins shows a green test stage.

**Rate limiter over-applied** — `User/server.js:32-33`: remove the router-level `app.use('/api/v1/users', authLimiter)`; apply the limiter directly on the `/login` and `/register` route definitions only. Verify: repeated profile fetches don't hit 429; login still throttles after repeated attempts.

**HPA fights ArgoCD selfHeal** — remove the hardcoded `replicas: {{ .Values.replicaCount }}` from `user-deployment.yaml` so the HPA owns it; if the template needs the field present, instead add `ignoreDifferences` for `/spec/replicas` on that resource in `argocd-application.yaml`. Add HPA resources for Product, Cart, and Frontend mirroring `user-hpa.yaml`. Verify: trigger a scale-up and confirm the next ArgoCD sync doesn't revert it.

**No timeout/retry Cart→Product** — `Cart/controllers/cartController.js:18,43`: add a 3000-5000ms `timeout` to both axios calls plus basic retry via `axios-retry` (2 attempts, exponential backoff). Full circuit-breaker is optional, not required. Verify: stop/delay Product and confirm Cart fails fast or retries instead of hanging.
